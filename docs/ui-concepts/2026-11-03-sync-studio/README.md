# Codex Sync 桌面界面设计稿

本稿是针对现有软件的界面方向探索，保留现有 Logo 与青蓝色品牌特征，采用更克制的桌面效率工具布局。文件位于软件项目中，未替换正式 Tk 界面，也未读写真实会话或连接 GitHub。

## 为什么适合这个方向

产品的核心任务是“判断本机缺少哪些会话，核对内容，安全导入”，用户最关心的是同步范围、已有会话是否受保护、出了问题能否撤销。最适合的类型是 macOS 桌面效率工具：低饱和中性底、明确的操作层级、紧凑且可读的列表、就地预览。

Logo 中的深色容器与青蓝色同步箭头已经传达技术与连接感。界面应把这种色彩用于当前选择与主要动作，避免整屏荧光强调。现有大面积深蓝和多个同等高亮按钮会竞争注意力；粗表格边框、长路径与底层数据库名占据首屏，用户需要自己从诊断信息中推导下一步。

## 本稿的变化

- 概览先回答“能否同步、有什么可导入”，再提供最近操作与撤销入口。
- 本机保护规则在概览和导入页均可见：正文、标题、项目归属及工作目录保持原样。
- 时间、项目及标题搜索集中在导入列表上方；不按来源设备分组。
- 导入工作区采用会话列表和右侧常驻对话预览，减少来回打开弹窗。
- 一次只有一个突出的主要动作；上传、检查和核对退为次级动作。
- 诊断详情按需展开，完整路径和日志集中放在设置中。
- 以中性炭黑而非高饱和深蓝作底，保留青蓝主操作、柔和绿色成功状态。系统字体与细分隔线保证熟悉感。
- 附浅色版本，用于较亮的办公环境；这不是确定默认主题的用户偏好。

## 文件

- `index.html`：可直接用浏览器打开的交互原型，含导航、筛选、搜索、对话/完整记录、标题暂存和主题切换。
- `01-overview-dark.png`：1440 × 960 视口、2 倍像素的深色概览图。
- `02-sync-dark.png`：相同视口的同步与导入图。
- `03-overview-light.png`：浅色概览图。
- `check-920.png`：较窄桌面窗口的布局检查图。
- `verification.json`：交互与横向溢出检查。
- `design-check.json`：一次机械设计检查的原始结果；其小字号发现已修复；分区与标签下边线的无外层内边距提示按实际子项间距复核，不把分栏容器当作文字容器处理。
- `assets/logo.svg`：来自项目既有 `assets/logo.svg`，保留原始标志。

所有数字、时间、连接状态、会话内容与操作历史均为示例。原型的导入及上传按钮仅提供演示反馈，不执行同步。

## 验证与落地边界

已用 Chrome 实际渲染并查看图片，检查 1440、1120、920、740、390 像素宽度下的各页面，无页面或主内容横向溢出。校验了导航、时间和项目筛选、搜索空态、本机会话标题保护、对话与完整记录切换、新增标题编辑及主题切换。

正式落地时应将真实同步计划和后台状态接入这些区域，并保留退出相关程序、源文件校验与撤销点等既有约束。HTML 原型表达信息组织和视觉目标；Tk 控件无法逐项直接复用 CSS，正式窗口的样式还需实现与平台验证。
