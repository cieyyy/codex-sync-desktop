# 项目文档的最小文字同步

## 现状与实现

原版只遍历 Codex 活动会话，删除媒体和附件二进制后上传文字记录。它不读取项目中的 Markdown、Word、Excel 文件。即使会话提到本地文件路径，其他设备也无法据此读取原件。

新增 `core/documents.py`，仅扫描明确指定的项目目录。输出放入同一个私有同步仓库的 `documents-text/devices/<设备>/<项目标识>/`；每个原文件对应一个 UTF-8（通用文字编码，用于跨设备保存中文）文字副本。会话导入逻辑不涉及这些副本，其他设备直接读仓库即可。

| 文件 | 同步内容 | 边界 |
| --- | --- | --- |
| `.md/.markdown/.txt/.csv/.tsv` | 正文，统一换行 | 输入要求 UTF-8；编码错误记为失败 |
| `.docx` | 正文段落、表格行列、页眉页脚、脚注尾注 | 不保留排版、图片、绘图、嵌入文件；复杂文本框或修订不保证完整语义 |
| `.xlsx` | 工作表名称及显隐状态、稀疏单元格地址、类型、值、公式、样式编号、合并区域 | 不重算公式；缓存值可能为空或过期；日期可能为序列值；不保留图表和样式定义 |
| `.doc/.xls/.docm/.xlsm` | 失败条目 | 先在原应用中另存为 `.docx/.xlsx` |

不做 AI 摘要，不删减已提取的正文。单文件源及输出上限各 32 MiB，Office 解压总量上限 64 MiB；超过限制明确记为失败，不静默截断。文档提取使用 Python 标准库；压缩会话归档额外使用 zstandard（压缩格式支持库，用于读取 `.jsonl.zst` 归档）。

## 本机全部会话及引用文档（本次采用）

首次在源码目录准备运行环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install .
```

Windows 中将 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`。

```bash
.venv/bin/python -m codex_sync_desktop.core.conversation_documents \
  --vault '../project-sync-vault' \
  --device 'macbook-all-conversations'
```

扫描本机 `sessions` 和 `archived_sessions` 中的 `.jsonl` 以及压缩 `.jsonl.zst` 归档，导出完整会话文字。通过会话元数据的工作目录、明确的绝对路径、带引号的相对路径和 Markdown 链接定位文档，仅提取实际引用的文件，不遍历整个工作目录。

路径提取为启发式：脚本动态拼接、附件仅存远端标识、复杂转义路径可能无法识别；无法定位的候选路径记录在 `unresolved` 中，并不等同于全部真实缺失文件。不会读取其他设备上才存在的原件。文档是当前磁盘内容，不能还原会话当时的历史版本。

索引为每份文档记录 `source_path`（原路径，用于追踪来源）和 `sessions`（引用会话清单，用于关联上下文）。同一原文件多次被引用只提取一次；不同文件即使文字相同仍各保留来源。

加 `--documents-only` 只刷新文档；加 `--save-settings` 会把目标仓库、设备名、本机 Codex 目录及“包含归档”和“提取引用文档”选项保存到桌面应用现有设置，后续使用本次修改的源码版执行原有同步按钮即可。未传该选项不会改变已有桌面设置。引用文档模式优先于手工 `document_roots`，两种模式不会覆盖混写同一设备索引。

这次范围是会话文字与可读取的引用文档；不复制认证文件、状态数据库或媒体二进制。当前对话仍在写入，导出是读取时的快照，不包含导出后新增的记录。

## 单独导出（无需退出 Codex）

在本项目目录运行，项目标识仅允许英文字母、数字、下划线和短横线；所有设备使用相同项目标识，路径可以不同。

```bash
python3 -m codex_sync_desktop.core.documents \
  --vault '/本机/project-sync-vault' \
  --device 'macbook' \
  --project 'model-tests=/本机/模型测试项目'
```

可重复传入 `--project` 指定多个目录。此命令只导出文字，不自动提交或推送。

加 `--save-projects` 可将这次传入的全部项目目录替换保存至桌面应用设置的 `document_roots`；之后源码版应用的“导出并推送”和“一键同步”会同时提取文档。该选项不修改应用已配置的同步仓库和设备名，首次配置时请将它们设为同一目标。已发布的旧安装包不包含本功能，需要使用本次修改的源码运行。

也可直接在现有应用配置中加入：

```json
{"document_roots": {"model-tests": "/本机/模型测试项目"}}
```

这是配置字段示例，应合入原配置，不能用它覆盖整个配置文件。

## 上传与其他设备读取

在目标私有仓库执行：

```bash
git pull --rebase --autostash
git add documents-text
git commit -m 'docs: refresh project document text'
git push
```

无变化时不需要创建提交。正常日常操作优先先拉取，再执行导出，最后提交和推送。应用内部导出入口沿用既有推送流程，不会自动修改任何 Git 历史。

其他设备先拉取仓库，再读取 `documents-text/README.md`，按各设备 `index.json`（文件索引，用于定位当前可读副本）的 `text_path` 打开正文。只读取 `status=ok` 的条目，必要时核验 `text_sha256`；SHA-256（内容校验算法，用于判断文件是否变化或损坏）基于 UTF-8、LF 换行的文字。Windows 检出若转换了换行，核验前先统一为 LF（换行符，用于保持跨系统内容校验一致）。

## 增量、错误和清理

- 正文和索引未变化时不重写；不写每次导出时间，避免空更新。
- 同一设备同一项目的同一路径更新文字副本；设备分目录，避免互相覆盖。
- 不扫描隐藏文件夹、`.git`、`.codex`、虚拟环境、依赖目录及符号链接；嵌套同步仓库也排除。
- 此功能按文档扩展名筛选，不使用 `.gitignore`，因为项目报告可能本来就被 Git 忽略。指定目录内符合格式的文档均会处理，包括 Excel 隐藏工作表；正文不自动脱敏。
- 文件损坏、编码错误、不支持格式均写入索引错误条目，命令退出码为 1；桌面同步显示文档失败数。
- 源文件消失后不再列入当前索引；旧文字副本和 Git 历史不会自动删除。读取方以最新索引为准，不能递归遍历旧副本当成当前文档。
- 清空 `document_roots` 会停止后续提取，既有索引及历史仍保留；若要永久清理，需另行明确选择范围。
- 原件不会被修改，也不会将副本恢复到目标设备的原路径。
