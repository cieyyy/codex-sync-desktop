# Codex Sync Desktop 总体方案

> 文档日期：2026-07-31  
> 当前源码版本：`0.7.2b2`，本地 `main` 提交 `821f33b`  
> 适用目标：Windows 10/11、Intel macOS、Apple Silicon macOS  
> 状态说明：本文描述目标方案与当前实现；未完成部分会明确标注。

## 1. 产品目标

Codex Sync Desktop 用一个由用户自己控制的 GitHub 私有仓库，在多台 Windows/macOS 电脑之间同步 Codex 活动会话的完整文字记录，使用户换设备后能够：

1. 拉取其他设备导出的会话。
2. 预览新增、相同、自动合并、失败和标题更新。
3. 将会话导入本机 Codex。
4. 修复 SQLite 与 `session_index.jsonl`，让任务重新出现在侧栏。
5. 在新设备继续原任务，而不是只阅读摘要。

它不是实时云盘，也不会同时远程控制所有设备。“一键同步”只操作当前正在使用的电脑，并通过 GitHub 仓库与其他设备交换数据。

## 2. 核心原则

### 2.1 私有仓库是唯一中转站

- 每台设备只与同一个 GitHub 私有仓库交换数据。
- 不依赖 U 盘、OneDrive、Obsidian 或额外网盘。
- 每台设备使用独立设备目录，避免不同电脑直接覆盖彼此数据。
- 仓库必须保持私有；发现同名公开仓库时，首次配置应停止。

### 2.2 内容相同与否由内容决定

- Task ID 只用于识别同一会话，不作为去重的唯一判断。
- 先规范化记录，再根据消息内容、类型和时间比较。
- 本机已包含来源全部内容时判定为相同。
- 同一会话两侧各有新增内容时，按语义记录和时间合并。
- 不生成供用户手工处理的冲突副本，冲突在后台自动合并。

### 2.3 导入前可验证、导入后可撤销

- 导入前校验清单路径和 SHA-256。
- 导入前生成事务撤销点。
- 导入失败不应留下半完成索引。
- 默认只保留最近一次可撤销备份，减少磁盘占用。
- 一键清理属于永久操作，执行前必须确认。

## 3. 数据流

```text
设备 A 的 ~/.codex/sessions
        │
        ├─ 读取活动会话和真实任务标题
        ├─ 移除图片、附件二进制和超长媒体块
        ├─ 保留完整文字、工具、命令、推理和敏感字段
        └─ 生成 SHA-256 manifest
                 │
                 ▼
GitHub 私有仓库/sessions-text/devices/<设备名>/
                 │
                 ▼
设备 B 拉取仓库
        │
        ├─ 校验 manifest、路径和文件哈希
        ├─ 生成导入计划和完整内容预览
        ├─ 创建事务撤销点
        ├─ 复制缺失会话／按内容和时间合并差异
        ├─ 应用最终任务标题
        └─ 修复 SQLite + session_index.jsonl
                 │
                 ▼
设备 B 的 Codex 侧栏和本地会话
```

## 4. 仓库结构

建议保持以下逻辑结构：

```text
sessions-text/
  devices/
    <device-slug>/
      manifest.json
      sessions/
        YYYY/MM/DD/rollout-....jsonl
```

约束：

- `device-slug` 必须在每台物理设备上唯一且稳定。
- 不要让同一物理设备长期使用两个设备名，否则会产生重复来源。
- 不上传整个 `.codex` 目录。
- 不上传 `auth.json`、原始 SQLite/WAL、附件目录和图片二进制。

## 5. 同步范围

### 5.1 保留

- 用户消息。
- 助手消息。
- 命令和工具调用。
- 工具输出。
- 任务状态。
- 推理文字。
- Token、密钥、密码、连接串及其他会话内敏感字段。
- Codex 任务标题、Task ID、时间和会话元数据。

### 5.2 删除或不上传

- 图片内容。
- 附件二进制。
- 内嵌媒体 Data URL。
- 超长二进制/Base64 块。
- 独立认证文件。
- 原始 Codex 数据库。
- 已归档或已从活动会话目录删除的会话。

重要：当前策略不是“秘密脱敏”。会话文字中出现的 Token、密钥和密码仍会进入私有仓库，因此必须按生产密钥仓库标准控制访问权限。

## 6. 首次配置方案

### 6.1 四步向导

1. 隐私和私有仓库确认。
2. GitHub 网络与代理检查。
3. Git、GitHub CLI 和 GitHub 登录。
4. 创建或连接私有仓库并首次上传。

### 6.2 全新设备登录

全新设备不要求用户提前运行命令：

1. 软件检测 Git 和 GitHub CLI 是否真实可启动。
2. 缺少 GitHub CLI 时，Windows 使用校验过的官方便携包；macOS 使用官方安装包。
3. 点击登录后显示由向导拥有的居中安全确认框。
4. 软件调用操作系统默认浏览器打开 `https://github.com/login/device`。
5. GitHub CLI 发起设备授权并尝试复制一次性验证码。
6. 用户只在 GitHub 官方页面输入账号、密码和二次验证码。
7. 软件后台等待并持续显示进度。
8. 授权完成后执行 `gh auth status` 复检。
9. 自动执行 `gh auth setup-git`，使 Git 能访问私有仓库。
10. 浏览器未打开时提供“重新打开授权页”。
11. 剪贴板不可用时去掉复制参数并自动降级重试。

软件不能读取、保存或代替用户输入 GitHub 密码和二次验证码。

### 6.3 网络与代理

- 优先读取 Windows 系统代理或 macOS `scutil --proxy`。
- 未写入系统代理时探测常见本机 HTTP 代理端口。
- 只接受不含账号密码的 HTTP/HTTPS 代理 URL。
- HTTPS 使用可信 CA 验证，不关闭证书校验。
- 网络失败必须展示原因和恢复路径。

## 7. 日常同步模型

### 7.1 拉取仓库

作用是把 GitHub 私有仓库的所有设备目录更新到当前电脑的本地同步仓库。它不是只拉取下拉框中选中的设备；来源设备选择发生在导入阶段。

拉取失败时的软件自愈：

- 识别认证失败、权限不足和无法读取远端仓库。
- 检查 GitHub CLI 登录。
- 重新配置 Git 凭据。
- GitHub SSH 地址失败时转换为 HTTPS。
- 自动重试一次。
- 不修改会话、数据库或索引。

### 7.2 导出并推送

1. 重新扫描本机活动会话。
2. 更新当前设备目录。
3. 清理当前设备目录中已经归档或删除的旧副本。
4. 提交 Git 变化。
5. 推送到 GitHub。
6. HTTP/2 上传中断时自动使用 HTTP/1.1 重试。
7. 即使本次没有新文件，也继续推送上次失败后遗留的本地提交。

### 7.3 预览导入

- 点击动作行查看对应会话。
- 自动合并可切换来源、本机和合并后版本。
- 完整显示所有可渲染记录，不截断。
- 只流式加载当前选中的版本，避免一次性占用过多内存。
- 可以修改最终标题；正式导入时才写入 Codex。

### 7.4 导入并修复

执行前必须退出 Codex、ChatGPT 和 Codex++：

1. 重新生成导入计划。
2. 应用预览阶段暂存的标题。
3. 创建事务撤销点。
4. 复制或合并会话文件。
5. 修复当前有效状态数据库的 `threads` 记录。
6. 重建或更新 `session_index.jsonl`。
7. 保留最近一次撤销点。

### 7.5 一键同步

- 未选择其他来源设备：拉取仓库，再导出并推送本机活动会话。
- 选择其他来源设备：拉取、导入合并、修复侧栏，再导出并推送本机。
- 只作用于当前电脑；其他关机或未运行软件的设备不会同时执行。

## 8. 标题策略

标题来源优先级：

1. 预览窗口中用户明确保存的最终标题。
2. 来源设备数据库中的有效人工标题。
3. 本机已有的有效人工标题。
4. 第一条有效用户请求生成的候选标题。
5. 最后才使用导入任务占位标题。

以下内容不能作为标题：

- `AGENTS.md instructions`。
- `<environment_context>`。
- 注入的系统或开发者上下文。
- 只有附件说明而没有实际请求的文本。

标题同时写入数据库可用的 `title`/`name` 字段和侧栏索引。

## 9. 磁盘和内存控制

- 仓库只保存文字 JSONL，不保存图片附件。
- 预览按当前选中会话和版本流式加载。
- 默认只保留最近一次导入撤销点。
- 日志使用轮转文件，总量约 2 MiB。
- 提供一键清理备份和一键清理日志。
- 不使用路径映射复制项目；会话中的原始项目路径只作为元数据保留。

Git 历史仍会保留旧版本内容，因此频繁修改大量会话会逐渐增大仓库。后续可增加仓库容量检查和受控压缩，但不能在未备份时自动重写 Git 历史。

## 10. 安全模型

- 自动创建和验证私有仓库。
- 只允许自动浏览器授权打开 GitHub 官方 HTTPS 页面。
- 用户凭据由 GitHub 页面和系统凭据存储处理。
- 导入前验证 manifest 路径不能是绝对路径、不能包含 `..`。
- 文件哈希不匹配时拒绝导入。
- 数据库写入前创建备份。
- 清理和回滚均需用户确认。

## 11. 跨平台策略

### Windows

- 检查 PATH、标准安装目录、注册表和软件私有工具目录。
- 后台运行 Git、GitHub CLI 和 PowerShell，不弹终端窗口。
- 使用稳定 AppUserModelID、统一图标、任务栏和 Alt+Tab 注册。
- GitHub CLI 优先使用免管理员权限便携版。

### macOS

- 同时支持 Intel 与 Apple Silicon 构建。
- 补充 Homebrew、MacPorts 和系统常见命令路径。
- 使用系统默认浏览器和官方设备授权。
- 缺少系统 Git 时打开命令行工具安装器。
- 当前发布未做 Apple 公证，首次启动可能需要右键“打开”。

## 12. 发布方案

### 稳定发布

- Windows：Setup.exe 与 Portable ZIP。
- macOS Intel：DMG/ZIP。
- macOS Apple Silicon：DMG/ZIP。
- 每个 Release 附带 `SHA256SUMS.txt`。

### 不使用 GitHub Actions 的手工发布

当 Actions 额度不足或明确禁止使用 Actions 时：

1. 在本地可信构建环境运行测试。
2. 本地构建 Windows/macOS 产物。
3. 使用不匹配 `v*` 工作流规则的手工 Beta 标签。
4. 直接上传 Release 资产。
5. 核对资产大小、SHA-256、目标提交和 Actions 运行数。
6. 不移动稳定版标签，不覆盖 `main`。

## 13. 当前未完成或需继续验证

- 预览窗口中“选择并永久排除某个会话，以后所有设备都不再同步”尚未实现；目前只有本机归档或删除会话会停止当前设备后续导出。
- 最新的浏览器登录和拉取认证自愈已进入本地源码并通过测试，但尚未重新打包发布。
- 最新改动仍需在真实的全新 Windows、Intel Mac 和 Apple Silicon Mac 上完成端到端登录验证。
- 安装包尚无 Windows 商业代码签名和 Apple Developer 公证。
- 不支持绕过企业网络策略、系统管理员授权、GitHub 密码或二次验证。
- 不提供多台设备同时在线的实时同步；每台设备必须主动执行同步。

## 14. 验收标准

发布前至少验证：

1. 全量自动测试通过。
2. 安装包可以安装、启动和卸载。
3. 全新设备无需命令即可完成工具准备。
4. 默认浏览器能打开 GitHub 官方授权页。
5. 账号密码和二次验证完成后软件自动识别登录成功。
6. 私有仓库创建、首次上传、另一设备拉取均成功。
7. 预览完整、不截断，标题修改可生效。
8. 导入后 Codex 侧栏可见且内容完整。
9. 同一会话差异按内容和时间合并，不按名称或 ID 粗暴覆盖。
10. 归档或删除会话不会在下一次本机导出中重新出现。
11. 导入失败能够撤销，清理操作有明确确认。
12. Windows 任务栏、Alt+Tab、图标和后台命令行为正常。
